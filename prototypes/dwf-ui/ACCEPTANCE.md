# Independent architectural design review

Read BRIEF.md and docs/dwf-ui-design-requirements.md. You are a demanding independent critic with browser access. Preserve candidate files. Use your own isolated browser and ignored .evidence/<critic-name>/ for evidence. Both critics must independently inspect the SAME current revision.

Judge the requested LARGE improvement. Merely changing colors, margins, font sizes, tiny focus treatments or polishing the old composition is insufficient even if usability tests pass. Require a coherent, visibly different structural solution within the chosen family and clear evidence that it makes workflows easier to understand. Identify the structural improvements, not just a list of cosmetic fixes. Do not demand similarity to the previous layout.

Automatic generation is central. Inspect the reusable graph-to-view/layout implementation, exercise every supplied graph fixture, and try a modified or independently added graph (rename/add a node, alter group size or a back edge) without manual coordinates. Evaluate resulting pictures. A hand-crafted SVG for each fixture, hidden identity-specific coordinates, or generic generation that produces cluttered/unreadable maps fails acceptance. Check stable layout when active status and historical selection change.

Independently inspect 1440x900, 1280x720, 1024x768 and 390x844, plus enlarged text/zoom, long labels and a short viewport. At normal desktop size the core examples should explain their architecture immediately and essential text must be readable, without collisions or misleading routes. Larger graphs may require pan/zoom/disclosure but need clear orientation and readable focus. Check all research/build routes, group memberships, return/result distinctions, fresh versus continuing session IDs, and selected invocation correspondence.

Exercise run selection, primitive and participant selection, old/latest invocation, skills, task/result, exact copied command and truthful clipboard failure fallback. Check keyboard access, modal/focus behavior where applicable, narrow-screen navigation and reduced motion. Check offline/local serving and absence of unnecessary external assets. No JSON panels or wave-navigation UI.

Give honest integer scores 0–10 for design and usability. Both must be 10 and remaining_issues empty to approve. A technically valid but architecturally unchanged or auto-generated-unreadable result cannot earn 10. Do not inflate scores to end the loop. Criticisms must identify a reproducible problem or an explained structural failure and actionable improvement. Prioritize the user's architecture and automatic-generation goals rather than an endless sequence of personal micro-style preferences. Report meaningful limitations explicitly.

Return JSON with outcome approve/changes/blocked, summary, scores:{design:N,usability:N}, architectural_improvements:[...], automatic_layout_evidence:[...], evidence:[actual viewport/interaction observations and screenshot paths], remaining_issues:[{severity,location,scenario,problem,required_change}]. Use blocked only for a genuine essential verification obstacle. No inherited approval from previous rounds. The framework sends the required result protocol too.
