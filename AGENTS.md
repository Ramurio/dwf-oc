# Правила работы

- Важные решения, особенно архитектурные, заранее обсуждай и согласовывай с постановщиком задачи — пользователем или агентом, который её поручил. Не принимай их единолично.
- К важным относятся изменения требований, внешних интерфейсов, архитектуры, хранения данных и договорённостей о приёмочных тестах.
- Перед согласованием кратко изложи варианты, последствия и свою рекомендацию. Дождись решения до реализации зависящей от него части работы.
- Уже согласованные решения выполняй без повторного разрешения. Локальные детали реализации выбирай самостоятельно, если они не меняют договорённости.

## Независимая проба DWF

- Ведущий агент программно запускает внешнего тестера в свежей сессии OpenCode, передаёт обычное пользовательское поручение и получает журнал и отчёт без ручного переноса сообщений.
- Тестер получает скилл `dwf-oc`, сам составляет workflow и использует публичный CLI. Участники DWF выполняют задачу тестового проекта.
- Ведущий агент проверяет фактический результат, исправляет DWF и его инструкции, запускает регрессии и повторяет независимую пробу до требуемого результата. Он не реализует задачу тестового проекта вместо участников DWF.
- Повторные пробы одной задачи начинаются на отдельных копиях одной исходной ревизии стенда. Сессии, поручения, команды и отчёты сохраняются для разбора.

## GitHub

- Основной репозиторий проекта — https://github.com/Ramurio/dwf-oc, приватный. Пользователь разрешил вести его через локальные коммиты и push выполненных поручений.
- Публикуй законченные логические изменения после соответствующих проверок. Сохраняй авторство пользователя и учитывай изменения удалённой ветки перед публикацией.
- Задачи и существенные решения веди в Beads. Перед публикацией обновляй переносимый снимок задач командой `bd export -o .beads/issues.jsonl`. Снимок содержит задачи, зависимости и комментарии. Полная история Dolt хранится отдельно.
- Исходники общих скиллов поддерживаются в https://github.com/Ramurio/ramu-skills. Изменения их копий в DWF согласовывай с исходниками.
- Учётные данные, локальные базы, зависимости и сырые журналы испытаний хранятся вне публикуемых файлов. В коммитах сохраняй код, инструкции и проверенные обезличенные сводки, необходимые для воспроизведения.
- Полный текст поручения для автономного развития находится в `docs/autonomous-goal.md`. Полномочия из него действуют, когда пользователь выдаёт это поручение.
