# Сравнение системных инструкций

Серия выполнена 9 ноября 2026 года на движке `585fe4fa8c9c069b3cd699a9de661a369a31b1a6`.
Модель во всех запросах — `openai/gpt-6.1-sol-ultrafast`, reasoning `high`.
Сценарии, исходные файлы, ожидаемые решения и дополнительные инструкции сохранены в
[prompt-cases.json](../acceptance/prompt-cases.json).

## Условия

Сравнивались действующие системные инструкции и те же инструкции с добавлениями
`evidence`. Добавления предлагали явно сопоставлять требования с проверками,
перепроверять прежние отчёты и сохранять ограничения в итоговой сводке.

Движок, инструменты, скиллы, модель, исходные файлы и задания совпадали. Каждый
сценарий выполнялся дважды для каждого варианта. Во втором повторе порядок
вариантов менялся. Каждая попытка получала отдельный каталог и новые сессии.
В цикле доработки reviewer сохранял свою сессию между двумя обращениями.

Использовались `participantAgent`, `rolePrompt`, `connect`, `admit` и
`readExecution` выбранной ревизии. Системные инструкции передавались настоящему
native агенту, остальные параметры сохранялись. Проверялись фактические вызовы
инструментов и загруженные скиллы. Kernel sandbox ограничивала файлы попыткой и
замороженным runtime, сеть — сервисом модели и собственным OpenCode.

| Сценарий | Ожидаемый результат |

| Корректная валидация положительного целого | Одобрение reviewer |

## Повторение

Для каждой записи корпуса создаётся новый каталог с `index.mjs`, `check.mjs` и
`package.json`, содержащим команду `node check.mjs` для `npm test`. Ожидания и
отчёты хранятся вне доступного участнику каталога. Вариант `evidence` добавляет
соответствующий текст из `additions` к `roleSystemPrompt` и получает новый
идентификатор native агента по хешу системных инструкций.

Роли запускаются в порядке `roles`. Предыдущий результат передаётся через
`rolePrompt`, а orchestrator получает полную историю. Для `repair-cycle`
используется одна сессия reviewer на оба обращения. Остальные попытки независимы.
Оценка сопоставляет каждый outcome с `expected`, затем выполняет внешнюю проверку
исправленного экспорта и сверяет сводку с фактами.

Исполняемые сценарии исходной серии, native сообщения, полные конфигурации,
хеши промптов и результаты сохранены в закрытом проверяющем контуре. Корпус
относится к проверке инструкций участников. Проверки полного маршрута CLI,
восстановления, остановки и реальных проектов выполняются отдельными сериями.
