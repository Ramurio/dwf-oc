# Проверка продолжения

Воспроизводимые команды из корня **кандидата**:

```sh
npm ci
node --test workflow-continuation.test.mjs workflow-controls.test.mjs
node --test acceptance/continuation.test.mjs
npm test
npm run test:ui
```

`acceptance/continuation.test.mjs` использует кандидатный `node ./dwf.mjs`,
отдельные Git-проекты, SQLite/state и native OpenCode-профили, управляемый HTTP
**только для модели** и настоящий shell/Git. Восстановление выполняется публичной
командой, без изменения SQLite, owner или lease. После SIGKILL тест ждёт реального
истечения 30-секундной аренды. Тесты удалённой сессии намеренно используют native
API как fault injection, не редактируют его базу. Очистка принадлежит sandbox.

## Матрица сценариев

| Граница/случай | Наблюдение и проверяемый инвариант |
| --- | --- |
| `preparation_error` | ENOSPC до подготовки input: конкретная причина, тот же runId, затем полный цикл |
| `prepared`, `admission_started` | SIGKILL после соответствующего сохранённого checkpoint: прежние ID и байты |
| `accepted` | Native принял input, контроллер умер до сохранения ack: inbox не принимает второй input |
| `executing` | Native model request остаётся активным после смерти контроллера; continue подключается до release |
| `during_tool` | Реальный shell остаётся активным после истечения lease; continue не запускает второй worker |
| `result_read` | Native-результат прочитан, но не сохранён контроллером: используется прежний input |
| `persistence_error` | Ошибка сохранения после результата: завершённый worker не запускается заново |
| `transition` | Сохранённый успешный этап не повторяется после смерти контроллера |
| `before_group`, `after_group` | Пересборка/сверка Git-объединения успешных параллельных workers без их перезапуска |
| `before_implement`, `after_implement` | Сверка общего кандидата: один resultVersion и одна записанная интеграция |
| `before_merge`, `after_merge` | Сверка исходного Git HEAD/дерева: нет второй интеграции или нового коммита |
| HTTP 403, сетевой обрыв | Причина сохранена; native retry либо отдельная записанная попытка в прежней сессии |
| Ошибка участника группы | Повторяется только сбойный участник, успешный worker и соседние проверки сохранены |
| Ошибка manager при implements | Сохраняются результаты scoped-участников и единственные интеграции |
| Одновременные/повторные continue | Один новый допуск; работающий/успешный запуск не получает второе поручение |
| Stop во время команды | Реальный эффект сохранён; без флага cancelled не открывается, без решения команда не повторяется |
| Confirm неопределённого эффекта | Записано свидетельство пользователя, затем настоящие reviewer/verifier, не синтетический approve |
| Изменение файлов | Старые approvals не используются, успешный неизменившийся worker не повторяется |
| Недоступная сессия | Явное решение, новая сессия со saved context и честным предупреждением об утраченных native-сообщениях |
| Legacy planner | Running/succeeded не преобразуются; failed сохраняет исходную запись и продолжает ту же сессию |

На `admission_started` отсутствие native-сессии не доказывает, что она никогда
не существовала. Матрица явно разрешает replay через resolution с проверенным
свидетельством fault marker; это не автоматический обход неопределённости. Для
такого неподтверждённого ввода сохраняются **исходные** ID и байты. При уже
подтверждённом вводе потерянная сессия требует отдельной новой попытки.

Unit/fenced-store проверки дополняют матрицу: stale owner после takeover, stop
против admission/finalization, сохранение полного taskContext и frozen bytes,
аннулирование разрешения при изменении дерева **до фактического send**, replay
потерянного ack уже принятого ввода, abort без открытия запуска, неизменяемые
префиксы аудита, malformed/legacy данные и исходы коррекции ответа.

## Границы свидетельства

Это детерминированные native/CLI-регрессии с реальными процессами и независимой
проверкой фактических файлов/Git, не оценка качества живой LLM и не отчёт внешнего
автономного тестера. Отдельная свежая сессия внешнего тестера для независимой
пробы запускается ведущим; её результаты нельзя приписывать этим тестам.
Реальный полный диск не создаётся: ENOSPC вводится на границе через test-only
module hook. Секреты и сырые sandbox-журналы не входят в публикуемые материалы.

## Исправления по независимому ревью continue

Все шесть замечаний воспроизведены до исправлений: восемь новых проверок
завершились ошибкой (зависшие остановленная/повторно сбойная группы, потеря
частичного writer-workspace, пропуск прежней review-group после drift,
неверная scientist phase/committee result и два случая stale permission).

- Барьеры admission/completion группы учитывают только текущие попытки;
  superseded-записи остаются в истории, но не препятствуют завершению.
- Неподтверждённый child проверяется по границе родителя; `admitted/error`
  не маскируются локальным `admissionStarted:false`. Добавлена также проверка
  такого legacy-состояния. Два последовательных HTTP 403 одного child
  восстанавливаются отдельными inputs в прежней сессии.
- Retry writer-группы продолжает её сохранённое частичное дерево. CLI-проба
  проверяет реальную запись файла до provider failure, тот же путь после retry
  и наличие обоих результатов после интеграции.
- Устаревшие checking-результаты ищутся также в прежних группах. Граница
  `worker → review-group → verifier` после drift проходит свежую группу и verifier,
  не повторяя успешного worker.
- Scientist phase, число research rounds и итог committee используют логические
  этапы без superseded-попыток; все попытки сохраняются в аудите. CLI-проверки
  подтверждают первый scout после сбоя scientist и точный отчёт после сбоя committee.
- План разрешения включает workspace наблюдаемых children/verifiers. Перед
  send проверяется также новый workspace retry; отдельные Git-worktree тесты
  меняют старый и новый каталоги после решения и требуют отказа stale permission.

Это регрессии исполнителя по замечаниям независимого reviewer, а не утверждение
о повторном независимом одобрении. Результаты прежних полных проверок выше
относятся к прежним файлам.

После исправлений полный `npm test` прошёл: 38/38 harness, 244/244 product,
116/116 runtime (включая полную fault-matrix и шесть новых CLI-регрессий),
12/12 Cucumber-сценариев / 116/116 шагов. `npm run test:ui` завершился с кодом 0,
`git diff --check` чист. Принятый UI QA-патч и снимок Beads остались без изменений.
Все команды завершены; новая независимая review/verifier-проверка и внешний
end-to-end xit.6 остаются ответственностью ведущего/DWF.

## Повторное ревью: порядок recheck и фактически отправляемые inputs

Три следующих замечания воспроизведены пятью падающими регрессиями:
второй worker после reviewer.changes (HTTP 403 и SIGKILL при работающем shell),
смешанная группа с успешным writer, и confirm/retry прерванного checking-child
после drift. После исправлений эти пять проверок проходят.

Исторический recheck не становится текущим, пока остаётся незавершённая работа
или активный native input. Уточняющая unit-проверка также покрывает failed
aggregate с незавершённым worker. CLI-проверка реального shell ждёт истечения
аренды после SIGKILL, подтверждает тот же current input и требует его успешного
результата/файла завершения до финального успеха.

Recheck группы теперь создаёт новые inputs только checking-участников через
обычную подготовку retry: каждый получает recoveryId, previousInputId и именно
свои resolution decisions до фиксации prompt. Перед send изменение проверенного
каталога аннулирует confirm/retry. Успешные non-checking inputs/results сохраняются;
уже интегрированные writer input IDs не применяются повторно. Для ещё не
интегрированного сохранённого writer-патча сохраняется его исходная база.
CLI-regression проверяет один input writer, один фактический эффект и сохранение
постороннего drift после успешного завершения смешанной группы.

Предыдущие полные прогоны выше относятся к предыдущим файлам; это не замена
повторному независимому review/verifier и не внешняя автономная проба.

Полный прогон после этой ревизии: `npm test` завершился с кодом 0 — 38/38
harness, 247/247 product, 119/119 runtime, 12/12 Cucumber-сценариев и 116/116
шагов. Повторный `npm run test:ui` — код 0; `git diff --check` чист.
Принятые UI QA-файлы и Beads совпадают с ранее согласованным main `50c80a6`.
Команды завершены. Неизменны ограничения: controlled model provider, ENOSPC
через test-only injection, Chrome-only UI и отдельный будущий автономный xit.6.

## Повторное членство результата не является новым выполнением

Замечание о дублировании retained writer подтверждено отдельными падающими
UI/context unit-проверками и CLI-сценарием с тремя последовательными recheck.
До исправления один input отображался четырьмя вызовами в UI, а history.json
повторял тот же результат. Проекции теперь оставляют первое хронологическое
вхождение inputId: исходное место вызова и порядок сессий сохраняются, все
отдельные checking inputs остаются отдельными. Legacy-записи без inputId не
объединяются по предположительной идентичности.

Членство writer во всех четырёх группах остаётся в сохранённом состоянии,
история контекста также содержит четыре отдельных group envelopes. Расширенная
CLI-проверка сравнивает точные массивы вызовов/отчётов, не скрывает дубли через
Set: writer — один, reviewer — четыре, verifier — четыре (в контексте перед
последним verifier — три уже выполненных). Фактический writer-эффект остаётся
однократным. После исправления три адресные проверки проходят; прежние полные
прогоны выше относятся к прежним файлам.

После устранения дублей полный `npm test` прошёл: 38/38 harness, 249/249 product,
119/119 runtime, 12/12 Cucumber-сценариев / 116/116 шагов. `npm run test:ui`
завершился с кодом 0; `git diff --check` чист. Принятые UI QA/Beads сохранены,
команды завершены. Это проверки исполнителя, не новое независимое одобрение;
внешняя автономная xit.6 и прежние ограничения остаются отдельными.
