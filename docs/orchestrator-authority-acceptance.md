# Решения orchestrator и материалы участников

Пользователь делегировал технические решения orchestrator. Worker обсуждает
варианты с ним; ведущий обеспечивает доставку и сохраняет решения, не создавая
дополнительной очереди пользовательских согласований. Принятые пользовательские
решения сохраняются при отмене исполнения. Исключения описаны в AGENTS.md.

Системная роль определяет полномочия и формат ответа. Методический скилл
`workflow-orchestration` описывает согласование общих интерфейсов, оценку
вариантов, передачу решения и работу с доказательствами. Launcher `dwf-oc`
передаёт эти полномочия в схему и сохраняет границы задач.

Материалы передаются через `artifacts` JSON-результата. В Git читается blob
отчётной ревизии; Git symlink, пути за пределами проекта и отсутствующие/неподходящие
файлы не дают доступ и отмечаются unavailable. Получатель читает неизменяемый
текст с исходными переводами строк; отдельный manifest хранит происхождение и
SHA-256. Разрешения на чужие live worktree не расширяются. При перезапуске
сохраняются исходные копии и привязка к попытке/ревизии.

## Независимая проба

Стенд: `acceptance/fixtures/orchestrator-authority`. Три задачи: исследовать
контракт, затем параллельно реализовать агрегацию событий и форматирование
отчёта. Публичные исходные тесты проверяют итог, нулевое/неизвестное время,
детерминированный порядок и сохранность ввода. Ведущий не реализует функции.
Внешний тестер в свежем OpenCode получает обычное поручение из
`acceptance/fixtures/orchestrator-authority-task.txt`, кандидатный launcher и
самостоятельно составляет схему, запускает публичный CLI, наблюдает и проверяет
результат. Модели: Astra xhigh для orchestrator/reviewer; Sol high для worker,
Sol xhigh для verifier, обычная скорость.

Для воспроизведения скопировать стенд во внешний каталог, инициализировать Git
и закоммитить исходное состояние. Нужна существующая авторизация OpenCode.
Повторные пробы используют отдельные копии одной исходной ревизии.

```sh
node acceptance/orchestrator-authority-trial.mjs \
  /absolute/seed /absolute/skills/dwf-oc /absolute/evidence \
  acceptance/fixtures/orchestrator-authority-task.txt
```

Harness сохраняет поручение, идентификаторы сессий/запуска, контексты и сообщения
без reasoning, проверяет интеграцию всех задач, отсутствие внешнего steer,
сохранность исходных тестов, наличие параллельной работы и повторно запускает
тесты результата. Сырые журналы и учётные данные не публикуются.

Первая проба обнаружила, что однострочный JSON-текст документа обрезался
инструментом чтения. Оркестратор вернул вопрос автору, не пользователю. Проба
остановлена, материал переведён в обычный текст; native-регрессия теперь читает
последнюю строку документа длиной более 8 KiB. Во второй пробе
`41d77d01-4fe8-4033-a48e-84aaa9371fa9` native read получил полный текст
(truncated=false). Orchestrator сам выбрал формат, записал D-001/D-002 и вернул
решение прежнему worker. Контракт прошёл review/verifier и был интегрирован
перед одновременным запуском summarize/render. В общем report.mjs возник
реальный конфликт: orchestrator адресовал исправление прежнему render/worker
без пользовательского решения, сохранив интегрированный summarize.
После повторного review/verifier все три задачи интегрированы. Общие reviewer
и verifier одобрили объединённый результат; DWF завершился succeeded и выполнил
финальный merge. Внешний тестер вернул итоговый отчёт программно: 36/36 тестов,
включая исходные 2/2, и 9 724 дополнительных составных случая. Ведущий независимо
повторил 36 тестов, проверил чистое рабочее дерево и сохранность исходных тестов.
Итоговая ревизия стенда: `51f66858f166f8f2938e0ffa84ccfea53d8f5dad`.

Не было пользовательских ответов или внешних команд steer. Ведущий проверил
живой UI: три блока implement раскрываются независимо, во время параллельной
работы отображались обе активные ветви; сохранены снимки 1440 и 390 px.
Это проверка работоспособности существующего UI, а не завершение открытых задач
его переработки. Переполнение счётчика в тестовом проекте проверено статически;
побочные эффекты getters/proxies остались вне выбранного контракта.

## Регрессии

- test:product: 254 проверки прошли; дополнительная проверка точных UTF-8/BOM
  и переводов строк прошла отдельно (report-artifacts: 6/6).
- test:harness: 43/43; test:runtime: 121/121.
- Cucumber controlled/recovery/workflow: 12 сценариев, 116 шагов прошли.
- Две новые native-проверки прошли: чтение конца длинного документа и отсутствие
  успешного verdict при сбое сохранения материала.
- Валидаторы обоих скиллов прошли; установленный launcher совпадает с каноническим,
  встроенный workflow-orchestration совпадает с исходником ramu-skills.

После старта второй пробы добавлены отдельные проверки и защита от принятия
verdict при ошибке сохранения, а также сохранение UTF-8 BOM. Эти границы покрыты
регрессиями выше; live-проба проверяет обычный путь передачи документов и
самостоятельных решений.
