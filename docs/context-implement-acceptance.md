## Воспроизведение

Нужны установленные зависимости с postinstall OpenCode, Chrome и штатный
авторизованный источник OpenCode. Никаких credential в аргументах/журналах:
`connectCandidateTester` использует только `authorizeTester`.

```sh
node acceptance/context-implement-trial.mjs \
  --seed "$HOME/.dwf/acceptance/context-implement-20261113/seed" \
  --baseline 5711a49919964e86821d3959c880f5c9b56d0d5e \
  --prompt-file "$HOME/.dwf/acceptance/context-implement-20261113/tester-task.txt" \
  --skill-directory "$HOME/.dwf/acceptance/context-implement-20261113/skill-candidate/dwf-oc" \
  --evidence "$HOME/.dwf/acceptance/context-implement-20261113/trial-evidence-final"
```

Каждый вызов использует `createAttempt`: чистый clone и проверка baseline,
отдельные session/input ID, HOME/XDG/OpenCode config/DB, собственные процессы.
Внешний tester — `openai/gpt-6.1-sol/high`, явно вместо ultrafast helper default.
Роли графа выбирает tester по обычному поручению: Astra 6 xhigh для orchestrator
и reviewer; Sol 6.1 high для worker, xhigh для verifier; всё на обычной скорости.
Глобальные продуктовые defaults не менялись.

Явный `bin/dwf` вызывает абсолютные Node и **кандидатный** `dwf.mjs` этого checkout.
Проверены `command -v dwf` снаружи и в настоящем native shell профиля тестера.
`connectTester(...,{skillDirectory})` проверяет всю установленную копию;
`checkTester` дополнительно сверяет path/body фактически загруженного native
скилла. Отличие любого файла требует свежего профиля, не молчаливой замены.

Test-only `--import` hook в изолированном окружении:

1. После фактически сохранённых двух native worker admissions убивает только
   контроллер. Native работа остаётся живой. На время опыта наблюдателям
   запрещён автоматический takeover, но публичный `continue` не модифицирован.
2. Harness ждёт настоящую аренду 31 секунду и вызывает `continue` того же ID.
   Frozen input/session/prompt/taskContext сверяются после завершения.
3. После двух реальных интеграций инъецирует явную ошибку нового admission
   orchestrator (не подмену ответа модели и не настоящий сетевой HTTP 403).
   Дожидается терминального failed с подтверждённой остановкой, снимает только
   этот fault и публичным `continue` продолжает тот же ID.
4. Проверяет прежние успешные visits, отсутствие дублей native inputs и
   идемпотентность continue после успеха. SQLite/owner/expiry не редактируются.
5. Дополнительный scoped `steer --kind decision` проверяет адресную ревизию,
   происхождение и фактический admitted input с точным текстом решения.

Конфликт настоящего Git в общих `src/index.mjs`/`registry.json` возникает из
независимых работ участников, не из написанного harness решения. Проверяются
адресный возврат в ту же worker-сессию, новая проверка и интеграция, ожидание
report до интеграций обеих зависимостей. Исходные acceptance-тесты сохраняются
побайтно как префиксы файлов; добавление усиленных тестов разрешено. Pristine
набор отдельно исполняется против интегрированного кода, без дописанного к тестам
кода, который мог бы скрыть сбой. Полный расширенный набор также исполняется;
HEAD сверяется с результатом DWF, рабочее дерево должно быть чистым.

`latest.json` указывает приватный каталог пробы: prompt, attempt, CLI/skill
provenance, visible messages без reasoning, report, crash/failed/final state,
native input IDs, интервалы реальных native-сообщений, исходные тесты и PNG/JSON.
При завершении или ошибке все собственные процессы останавливаются; raw-файлы
остаются вне Git для разбора.

Для повторного просмотра **реального сохранённого** успешного run с текущими
UI assets, без фабрикации состояния и запуска модели:

```sh
node acceptance/context-implement-ui.mjs <attempt-directory> <private-evidence-directory>
```

Скрипт сверяет UI API с оригинальным store/taskContext/prompt, общий Fit-граф,
3 integrated блока, историю вернувшегося worker и точные требования на 1440/390 px.

## Исправления и регрессии

После ревью устранено противоречие в entrypoint кандидатного launcher:
`SKILL.md` безусловно предлагал `start --preset --task-file`, хотя CLI отвергает
его для `taskPackages`. Теперь сначала `preset show`, затем непакетный shortcut
либо явное обновление пакетов и `start --file`, как в `references/cli.md`.
Проверка текста сначала падала из-за отсутствия `preset show`, после исправления
прошла. Кандидатным CLI в изоляции проверены save/show и отказ от подмены пакетного
поручения через task-file, обновлённая схема валидирована. Имеющаяся native-регрессия
непакетного пресета (`a completed run becomes a named preset`) повторно прошла.
Только эта редакционная поправка сделана после полных регрессий ниже; код продукта
и тестов не менялся. Живые пробы не повторялись с новым текстом/хэшем, поэтому их
свидетельства относятся к прежней копии, а не к исправленному entrypoint.

Живая мобильная проба выявила два дефекта длинного поручения: «Runs» распадалось
на четыре вертикальные буквы, zoom-кнопки выходили из toolbar и перекрывали
навигацию задач. Новая `acceptance/ui-long-workflow.mjs` сначала падала на
`4 !== 1`, затем отдельно на геометрии toolbar. `white-space` для подписи и
`flex-shrink:0` для мобильной панели устранили причины; проверки и PNG прошли
на 390/1440 px. Новый браузерный сценарий включён в полный `test:ui`.

Также проверены отказ от чужого launcher в профиле и runnable архив тестера:
после добавления зависимости `harness.mjs` архивный `tester.mjs --help` проходит
(до исправления содержательно падал с ERR_MODULE_NOT_FOUND).

Полный `npm test`: **43 harness + 249 product + 121 native/runtime = 413**
Node-проверок, **12** Cucumber-сценариев/116 шагов — всё прошло.
Отдельная новая native-регрессия реально убивает контроллер, ждёт аренду,
продолжает running и затем failed run публичной командой без правки базы,
сверяет прежние успехи и отсутствие повторных workers.
Полный `npm run test:ui`: **35** UI/layout unit-проверок и все браузерные
скрипты, включая новый long-workflow, — прошли после CSS-исправления.
`test:steps`: 13 сценариев/128 шагов разрешены dry-run; `git diff --check` чист.
